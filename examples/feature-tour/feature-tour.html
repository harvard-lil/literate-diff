Promote, do not rebuild

A feature tour of literate-diff on an invented two-repository change

2 repos · 16 files · +80 · −46
wrenprod...main10 files
wren-terraformmain...deploy-by-digest6 files

Before this change, every deploy built a fresh image on the prod branch and pushed it as latest, with production settings copied into the image at build time and long-lived AWS keys in the workflow. The suite never ran against the bytes that shipped.

After it, CI builds one image per commit, tests the test stage that is built from prod, and publishes it tagged with the commit. The deploy resolves that tag to a digest and ships the digest. The registry refuses to move a commit tag, keeps deployed images longer than candidates, and the deploy role trusts one GitHub environment rather than every branch.

The chapters run in dependency order: the registry has to accept immutable tags before the workflow can rely on them.

Wins

Security

  1. S1Before, the deploy trusted repo:example/wren:*, so any branch could assume the deploy role. It now trusts the prod environment only.↓iam.tf ↓deploy.yml
  2. S2Before, the workflow carried long-lived access keys as repository secrets. It now assumes a role over OIDC.↓deploy.yml ↓deploy.yml
  3. S3Before, actions were referenced by tag. They are pinned to a commit SHA.↓deploy.yml ↓deploy.yml

Correctness

  1. C1Before, the deploy rebuilt the image, so the bytes tested and the bytes shipped were two builds of the same source. The deploy now promotes the image CI tested, by digest.↓Dockerfile ↓deploy.yml
  2. C2Before, the production settings module was copied over settings.py at build time, so one image could only ever be production. The module is named at runtime, and one image boots as any tier.↓Dockerfile ↓__init__.py

Reliability

  1. R1Before, a re-run could repoint a commit tag at different bytes. Commit tags are immutable; only latest moves.↓ecr.tf
  2. R2Before, "keep last 5" expired the image production was running as soon as five more merges landed. Deployed images now age on their own rule.↓ecr.tf
  3. R3Before, health checks ran once a minute and old tasks drained for five minutes. Checks run every 15 seconds and the drain is 120, since the CDN gives up on an origin at about 100.↓ingress.tf

The other side

Regressions

  1. X1The dev image is no longer pulled, so a first checkout builds it, and a dependency change rebuilds it.↓dev: built locally, working tree mounted over it ↓README.md
  2. X2The maintenance page went with the second target group. There is no maintenance mode until an edge-served one exists.↓maintenance.tf

Future work

  1. F1A maintenance page held at the CDN, so it works when the origin is down; see Regression 2.
  2. F2Compiled assets served from a bucket rather than the container, so a rolling deploy cannot 404 on a bundle from the other version.↓settings_prod.py
